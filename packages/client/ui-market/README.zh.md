# @deepseek-ai/dsh-client-ui-market

[English](README.md) | 中文

## 概述

市场页面通过专家、技能、连接器和插件四个页签展示资源。用户通过同一个 Host 市场服务安装、更新和卸载市场包，管理技能开关和个人技能，以及连接和配置 MCP 服务。页面跟踪安装与连接器状态，并通过持久 toast 报告操作结果。

## 使用此包

将插件与 Web 客户端和 Host 市场 bundle 一起挂载。打开市场面板即可浏览技能分类、查看技能详情、安装技能并管理已安装列表。安装、切换或删除后页面会刷新技能名称和斜杠菜单候选项。

页面打开期间，新发布、已下架或有更新的条目无需离开页面即可显示。用户切换页签、窗口重新获得焦点或变为可见时，页面会重新读取目录；窗口可见期间每隔 `catalogRevalidateMs`（默认 60,000 ms）也读取一次，窗口隐藏时不做定时读取。每次读取都带上缓存的 ETag，目录未变化时只产生一次 304 响应，Host 也不为此推送快照。`catalogRevalidateMs` 是 `ui-market` 条目的 volatile 字段：在 `cordis.yml` 中修改后会同步到已打开的页面，并从下一次定时读取开始生效。后台读取失败不显示 toast，页面保留最近的目录及其离线提示。

在“技能”页签中，**添加技能 → 查找技能**会打开新对话、聚焦输入框，并预填“请帮我查找并自动安装能「」的技能”。在 `「」` 中补充所需能力后发送；发送前内容只保留为草稿，助手使用该对话中可用的能力执行请求。**创建技能**同样打开新对话，预填 `skill-creator` 技能引用和请求模板，不会自动发送。

**添加技能 → 上传技能**将一个本地 `.md` 或 `.zip` 文件导入为个人技能，不会打开对话。将文件拖入虚线区域或点击区域选择文件，查看名称和大小后即可安装。弹窗会列出压缩包结构和 YAML 文件头要求。拖入多个文件或文件夹时会提示错误，并保留之前的选择。Host 会在发布前校验技能和压缩包；支持的结构和安装目录由 [market-skills](../../market/market-skills/README.zh.md) 说明。同名技能会被拒绝而不替换，包括已停用的技能。错误保留在弹窗内，便于重试或换文件；连接中断导致结果不确定时，应先检查已安装列表再重试。上传成功后会打开已安装列表，并刷新斜杠菜单候选项。

每个已安装技能的详情弹窗都有同一个“更多操作”菜单，无论技能来自市场还是个人文件夹：

- **编辑**：打开新对话，输入框内容为 `/skill-creator 请帮我编辑 /<skill> 这个 skill`，两个名称都是技能引用，不会自动发送。
- **打开文件夹**：在 Host 的文件管理器中选中个人技能的说明文件。只有个人技能在 Host 报告有桌面且有文件路径时才显示；市场下载的技能不显示。
- **卸载**：先确认。市场技能通过市场卸载；个人技能会删除其文件夹。

Host 挂载了连接器类型时才显示“连接器”页签。**连接**会先安装尚未安装的连接器；第一次连接时显示连接器要运行的程序，用户接受后才启动。接受过的连接器可以直接在卡片上开关。详情弹窗显示连接器状态和启动失败原因，并提供重试、更新和卸载。

**添加连接器**用来添加用户自己配置的 MCP 服务：可以粘贴 MCP 项目给出的 JSON，一次可以有多个服务，保存前逐个列出并标出有问题的；也可以手动填写一个服务，包括整行命令或 URL、每行一个的环境变量或 Headers、超时，下方显示对应的 JSON。自定义连接器排在网格最前面，带“自定义”标签和命令或 URL，可以直接在卡片上开关。编辑时类型固定，要换类型就删除后重新添加。它的详情弹窗默认遮住环境变量和 Headers 的值，可以点开查看，并提供编辑和删除。启动失败时显示常见原因的提示、Host 给出的原因，以及程序最后几行 stderr；**让助手诊断**会新开一个对话，预填连接器的配置和失败信息，环境变量和 Headers 只列名字、不带值。

插件页签支持按标题、描述和包名搜索，并按发布的分类筛选。详情显示已安装版本，并允许选择已发布的版本。兼容性由 Host 提供；不兼容版本显示原因且不能安装。安装前需要确认，因为插件代码以用户权限运行，并影响当前配置中的对话。应用自带插件不能在此替换或卸载。插件开关和配置仍在插件管理页面调整。

市场包安装期间，卡片显示进度条，详情弹窗显示当前步骤：已下载的 MB 数、已解压的文件数，以及需要时不显示百分比的包安装步骤。插件与技能、连接器使用相同的 `market` 安装、更新、卸载、进度和 toast 路径。卸载插件前需要确认，之后 Host 会卸载运行时贡献并删除包文件。

<a id="understand-the-implementation"></a>
## 实现说明

客户端使用一个可观察 store 保存目录和已安装技能流。用户操作调用类型化 Remote 方法，并通过页面和持久 toast 展示成功或失败。调用和流走不同的通道，所以连接器调用的结果可能比连接器流里更新的一帧晚到；store 接受流里的每一帧，丢弃 `revision` 比当前显示的小的调用结果，这样已经再次失败的重试不会一直停在“启动中”。插件提供主面板、导航入口，以及 `ui-skill` 使用的技能显示名称。

<a id="model-experience"></a>
## 模型体验

### 已安装技能发现

#### 模型看到的内容

浏览页面不增加提示词。查找、创建、编辑和连接器诊断操作会准备可编辑草稿，只有发送草稿后才会将请求加入对话。启用技能会改变 `ctx.skills`，因此已有技能目录可以根据调用策略向模型展示它。

#### Token 影响

浏览页面时没有影响。之后调用技能时，现有技能消费者负责计算指令正文。

#### KV Cache 影响

没有直接影响；面向模型的技能内容由 Host 技能消费者负责。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- 页面需要 Host 提供市场 Remote 命名空间；目录端点离线时会显示最近一次可用的目录。
- 在页面上删除个人技能后无法撤销；文件会被直接删除，不会进入回收站。
- 编辑依赖 `skill-creator` 技能；组合中没有它时，引用会作为普通文本发送。
